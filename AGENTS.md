# AGENTS.md

Orientation for AI agents working in this repo. Keep this file up to date in the
same change whenever conventions, structure, or workflows change.

## What this is

My personal dotfiles, applied with a plain shell script (`./setup`). No Ansible,
no nix — just symlinks and a few helpers. Must run on **macOS and Linux** (an
Alpine Docker image runs `./setup`), so keep `bin/` scripts POSIX-portable and
avoid GNU-only/BSD-only flags.

## Layout

- `setup` — main install script (symlinks configs, installs tools, applies
  Copilot user settings with `copilot config` when available). The Copilot block
  reads `copilot config --list` once; `__copilot_config_set` skips exact `key=value` matches,
  including individual list entries. On macOS, it grants read-write sandbox
  access to the Rex server socket. Generates Fish completions for Rex and Copilot
  when each command is available.
- `copilot/config.ini` — static Copilot settings, one `key=value` per line.
  Values are literal; repeat keys for list settings. All installed plugin files
  share one read-only sandbox grant; Lever's data paths have separate write
  grants. Runtime paths stay in `setup`.
- `copilot/hooks/*.json` — global hooks, linked individually into
  `~/.copilot/hooks/` by `setup`. The Rex session-start hook supplies terminal
  context on start and resume. Hooks cannot be set with `copilot config`.
- `macos/set-defaults.sh` — macOS `defaults` writes. Run by hand, **not** by
  `setup`. The Mail and Safari sections need Full Disk Access to have any
  effect, since those prefs live in sandbox containers.
- `macos/set-dock.sh` — applies the host's Dock list and restarts only the Dock.
  Resolves app symlinks before writing Dock entries. Run it separately to
  update icons without applying other macOS defaults.
- `macos/rex-settings.sh export|import` — saves or applies selected Rex app
  preferences from `rex/settings.plist`. The plist's keys are the export
  allowlist; never export the whole preference domain into the repository.
  Import merges preferences and requires Rex to be closed. `setup` does not
  apply app preferences.
- `bin/` — personal scripts on `$PATH`. Keep portable.
- `bin/bazel-cleanup` removes Bazel output bases with missing recorded
  workspaces across projects. It skips unknown workspaces and server PID files;
  use `--dry-run` to preview and `--output-user-root` for a non-default root.
- `gh/extensions/gh-<name>/gh-<name>` — local `gh` extensions (`gh <name>`),
  linked into `~/.local/share/gh/extensions` by `setup`.
- `Taskfile.yml` — maintenance tasks (`task update`, `task release`), run with
  [Task](https://taskfile.dev).
- Copilot agents and skills live in `caarlos0/copilot`, not this repository.
  `setup` installs coding, security, fitness, terminals, coordination, and home
  from the `caarlos0` marketplace and updates installed plugins.
  After successful installation and update, it removes only agent/skill
  symlinks targeting this checkout's retired `agents/` and `skills/` paths.
  Real files, directories, and unrelated links are preserved. A disabled
  personal plugin stops migration without enabling it or removing links.
  User settings, personal instructions, MCP/LSP configuration, and external
  skill installs remain here. Plugin agents use qualified names such as
  `coding:caarlos0` and `coordination:general`; launchers must use those names.
- `Brewfile.<host>` — per-machine package lists (`darkmatter` is personal,
  `quasar` is work), auto-regenerated by `task update` via
  `brew bundle dump`; hand-edits don't persist unless the package is actually
  installed/removed. `dump` also silently drops App Store apps `mas` can't index
  (e.g. apps renamed on disk), so check the diff before committing.
- Per-tool config dirs: `rex/`, `fish/`, `nvim/`, `git/`, …

## Per-machine files

`darkmatter` is the personal machine, `quasar` the work one. `setup` keys off
`hostname -s`, so anything machine-specific is just a file named after the host,
and an unknown host silently gets the shared setup only:

- `Brewfile.<host>` — fully separate lists, so a `brew bundle dump` on one
  machine can't delete the other machine's packages. A package added on one
  machine has to be added to the other file by hand.
- `hammerspoon/apps.<host>.lua` — the app hotkey table, linked to
  `~/.hammerspoon/apps.lua`. `init.lua` is shared and binds whatever the table
  lists (`launchOrFocus` for one app, `appCycler` for several).
- `macos/dock.<host>.txt` — the Dock app list, one path per line. Read by
  `macos/set-dock.sh` (also called by `macos/set-defaults.sh`), which **replaces**
  the whole Dock with it; apps that aren't installed are skipped. Without a
  file for the host, the Dock is left alone.

Everything else is shared. Neither `setup` nor `brew bundle` uninstalls
anything: removing an app from a `Brewfile` doesn't remove it from the machine.
The only exceptions are explicitly retired repo-managed configuration, Copilot
agent/skill, and local `gh` extension links removed during setup migrations.

## Conventions

- Conventional Commits with scope (e.g. `fix(rex): …`), one logical change per
  commit, signed off (`-s`).
- Don't commit speculative work; wait for an explicit "commit".
- Integrate upstream branches with **merge, never rebase**.
- GitHub CLI procedures live in the coding plugin's `gh-cli` skill:
  use native required-check fail-fast watching for CI; `gh wait` for PR changes
  or default-branch commits; and `gh wait --merge` for completed merges.
  Do not use ad hoc sleep-and-poll loops.
- `bin/wt --tab/--split` and `bin/review` require Rex and `REX_SESSION`.
  `wt` owns Rex pane launching; `review` delegates to it. `wt .` uses the
  current directory without opening the worktree picker.
  `wt` runs in the new pane so fetch/checkout happen there;
  `WT_PANE` makes `fail` hold the pane open. `wt --pr` uses the PR's head branch
  name for the worktree and local branch. If the branch exists, it reuses its
  worktree (or creates one) and pulls without rebasing. Worktrees marked for a
  different PR are not reused. For `wt -- <command>`,
  Fish temporarily enables full job control so Rex sees the foreground
  command, then restores its prior job-control mode.
- Review policy lives in the coding plugin's `review` skill.
  `bin/review` only launches Copilot and selects continuous review with `--keep`. It takes any
  number of PRs: zero or one runs in the current pane unless `--tab`/`-t` or
  `--split`/`-s` is given; several require one of those flags.
  Reviews first assess whether the change is needed and belongs in the proposed
  layer, then compare alternative approaches before implementation details.
- Coordinator agents, lifecycle policy, board assets, and board checks live in
  `caarlos0/copilot`. Reviews use Rex session `reviews`; implementations use
  `work`. Durable handoffs remain in `~/.local/state/copilot-coordinator/`.
- Terminal theming: Catppuccin Mocha + Nerd Font glyphs.
- `p` uses the frecency-sorted project list in
  `fish/functions/__project_list.fish`.
- Rex Beta is the only macOS terminal, used by the Hyper+J shortcut and Dock.
  `setup` links `rex/themes`; import the theme separately because custom theme
  IDs are machine-local. `rex/settings.plist` preserves Berkeley Mono 12 and
  selected appearance preferences, but no server addresses, permissions, or
  session state. CLI client actions require Remote Control enabled in the app.
- Neovim updates are explicit: `task nvim` updates plugins, then installs missing
  configured Tree-sitter parsers and updates installed parsers in a fresh Neovim
  process, waiting for completion. The individual commands are
  `:lua vim.pack.update()`, `:TSInstallConfigured`, and `:TSUpdate`. Do not install
  parsers on startup or update plugins in `setup`.
